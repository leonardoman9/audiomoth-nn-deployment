# Verification of the WrenNet port to AudioMoth (21 October 2026)

Goal: confirm as much as possible, without a board, of what was in doubt. For each item: what was done, the result, and
what remains open. Everything can be repeated with the scripts named. Nothing has been run on the chip.

## 1. Microphone configuration at 32 kHz
The official AudioMoth configuration app script (`constants.js`) uses, for 32 kHz: `sampleRate 384000`,
`sampleRateDivider 12`, `clockDivider 4`, `acquisitionCycles 16`, `oversampleRate 1`; default gain medium.
**Matches** `main_app.c`. The ADC is 12-bit differential with a 2.5 V reference (±1.25 V, LSB 0.61 mV).

## 2. Watchdog
`WDOG` period 64k on the 1 kHz ULFRCO = ~65 s (`audiomoth.c`, reference manual). The longest block (the network) takes a few
seconds: **no risk**; the watchdog is fed in the loops anyway.

## 3. External SRAM: 8-bit bus with wait states (a finding that changed the design)
`enableEBI()`: D8A8 mode, read 2+3+1 cycles, write 6 cycles **per byte**: a 32-bit access costs ~25 cycles (vs 1 for
internal RAM). `enableExternalSRAM()` and `enableFileSystem()` return false on `AM_VERSION_4` hardware (USB Microphone: no
SD and no SRAM); the Dev board, which has both, must detect as < 4 (cannot be checked without a board).

Profile with a QEMU plugin (`tools/memcount.c`, counts instructions and bytes per memory region), one 3 s window:

| stage | first design | after the redesign |
|---|---|---|
| front-end (301 frames) | 68 M instructions, **86 MB** to external SRAM (~13 s: overrun, every window dropped) | 44.8 M instructions, 0.85 MB (~1.3–1.8 s, 45–60 % CPU while recording) |
| backbone (4-D model) | 105 M instr., 16.3 MB (activations: ~67 KB in the arena) | unchanged: ~4.9–6.2 s |
| C tail | 55 M instr., no external accesses | unchanged: ~1.4–2.1 s |

Front-end redesign: constant tables in flash (generated by `tools/gen_frontend_tables.c`), working buffers in internal RAM
(6 KB), 1024-point real FFT computed as a 512-point complex FFT plus a split step; only the sample ring and the dB
spectrogram stay in external SRAM (sequential accesses). Verified result: ≤ 1 int8 LSB vs PyTorch.
Estimate per window (CPI 1.2–1.8 on the instruction count, plus EBI delays): backbone + tail take 6–8 s after the 3 s
recording, i.e. ~27–31 windows in 5 minutes; energy ~0.8–1.0 J per window at 21 mA / 4.1 V (not 0.077 J as in the paper).
These are estimates, not measurements.

## 4. Stack and internal RAM
Maximum stack measured in QEMU over the whole pipeline: **2,708 B** (2.7 KB); pipeline statics 7,024 B. Full application:
`.data` 192 + `.bss` 14,112 B (+ 3 KB reserved heap). Wide margin on 32 KB.

## 5. Flash
Complete firmware (application + classifier): **230,124 B of 245,760** (15.6 KB margin). TFLM+CMSIS-NN 53.6 KB (size build,
no-int4 patch in `firmware/patches/`), model 94.7 KB, tail 27.5 KB, front-end tables ~10 KB. The original AudioMoth linker
script compares a LENGTH with an ADDRESS (`__etext`), which makes it 16 KB stricter than the physical limit; fixed in our copy
(`firmware/audiomoth_tflm.ld`). The rest of the firmware (FatFS, audiomoth.c, emlib, filters) is ~36 KB (diagnostic build
without the network). The complete original AudioMoth firmware was ~150 KB: FatFS with code page 932 (60 KB) and libc/printf
(33 KB); here FatFS is trimmed (CP437, 8.3 names, **no exFAT: FAT32 card**).

## 6. FatFS + AudioMoth file-system wrappers (test on a FAT32 image)
`tests/fstest/` (`run_fstest.sh`): the real FatFS with the trimmed configuration, plus the file functions of `audiomoth.c`
copied verbatim, on a 128 MB FAT32 image. **PASS**: CONFIG.TXT read and marked, 120 lines appended (open/write/close), files
read back correctly by an independent FAT reader (mtools). One defect found and fixed: `f_rename` fails if the target exists
(the simulator hid this); CONFIG.TXT is now overwritten with "APPLIED <time>". The SPI driver (`microsd.c`, vendor code,
unmodified) has not been executed: still to be tested on the board.

## 7. Clock and sleep
EM4 (RAM lost, BURTC kept): every wake-up is a reboot, as intended. Long sleeps use `powerDownAndWake(s, true)` (the
unsynchronised version would multiply ms*1024 and overflow beyond ~70 min), in 6 h chunks. The time is lost if power is lost
(datasheet): a new CONFIG.TXT is needed. Drift ±0.89 s/day.

## 8. Class order (error found, now confirmed on all species)
The real order is that of `allowed_bird_classes` (0 Bubo bubo, 1 Certhia familiaris, 2 Apus apus, 3 Certhia brachydactyla,
4 Emberiza cia, 5 Lophophanes cristatus, 6 Periparus ater, 7 Poecile montanus, 8 non-bird), not the one in the training log.
Direct test with real recordings from the project Drive (3 s windows, most-voted index per true species): Bubo 19/23 -> 0,
Certhia fam. 13/14 -> 1, Apus 20/23 -> 2, Certhia brach. 12/14 -> 3, Emberiza 13/23 -> 4, Lophophanes 10/14 -> 5,
Periparus 19/24 -> 6, Poecile 17/24 -> 7: **8 species out of 8**, 76 % of windows correct. Fixed in `schedule.c` and in the tools.

## 9. Accuracy on the real species (data from the project Drive)
161 windows of 3 s (the 2 loudest per file, 7–12 files per species), all 8 species.

| | accuracy |
|---|---|
| PyTorch float, clean audio | 76.4 % |
| device pipeline (C front-end + int8 backbone + C tail), clean audio | 75.8 % |
| PyTorch float, simulated analogue chain at 70 / 60 / 50 dB SPL | 73.3 % / 73.9 % / 73.3 % |
| device pipeline, simulated chain at 70 / 60 / 50 dB SPL | 75.8 % / 75.8 % / 75.2 % |

Per class (float, clean): Bubo 0.79; Certhia fam. 0.93; Apus 0.87; Certhia brach. 0.86; Emberiza 0.54; Lophophanes 0.71;
Periparus 0.79; Poecile 0.71. Reading: int8 + C cost < 1 point; the simulated analogue chain costs ~2–3 points on the float
model and almost nothing on the int8 pipeline.
**Limits:** small sample (±3–4 points), windows picked by energy rather than with the training's call extraction, no non-bird
windows, and the Drive files are probably also training files (absolute accuracy is optimistic; the relative comparison is
what counts). Scripts: `tools/bird_eval_prepare.py` + `tools/bird_eval_pipeline.py`; Xeno-canto download: `tools/xc_fetch.py`
(API key). These are in the WrenNet repository.

## 10. On-device test modes
`REPLAY.PCM` ("RPLY" + 96,000 int16 samples + "END!") on the SD card: the device classifies it and writes
`REPLAY,<log line with the 9 logits>`; tested in the simulator (difference 0.044 from PyTorch). Diagnostic build
`EXTRA_CF=-DBIRD_DIAG_RECORD firmware/app/build_app.sh ...`: records 3 WAV files (`HHMMSS.WAV`) without the network, 36 KB of
flash; tested in the simulator (5 % error above 300 Hz vs the 12-bit-quantised source).

## 11. Compiler: GNU Arm 10.3-2021.10 (the one the AudioMoth Makefile expects) vs 14.3.1
TFLM (same commit + patch) and the firmware rebuilt entirely with 10.3.1 20210824. **PASS**: 0 warnings in the library and
in the firmware (apart from the usual newlib `_read`/`_lseek` stubs), identical QEMU PCM->logits pipeline (max|d| vs host
0/1000, same argmax), stack 2,712 B.
Flash with the same TFLM flags:

| TFLM flags | GCC 14.3.1 | GCC 10.3.1 |
|---|---|---|
| `BUILD_TYPE=release` (kernels at -O2) | 244,620 B | 239,608 B |
| + `KERNEL_OPTIMIZATION_LEVEL=-Os THIRD_PARTY_KERNEL_OPTIMIZATION_LEVEL=-Os OPTIMIZE_KERNELS_FOR=KERNELS_OPTIMIZED_FOR_SIZE` | **230,124 B** | **230,024 B** |

The size flags are required (without them the margin drops below 1.2 KB with 14.3); with them the two compilers are
equivalent (-100 B). An earlier version of this section compared 10.3 without the flags against 14.3 with them, and was wrong.

## 12. Still open (needs the board or more data)
Boot and external SRAM enable on the chip; real DMA/ADC capture and levels; the real SD driver; real timing and power (the
estimates above can be off by ~2×); true accuracy on the test set (the Drive dataset lacks the training's test split, and
the `os.listdir` order is not reproducible); domain gap with real device audio.
